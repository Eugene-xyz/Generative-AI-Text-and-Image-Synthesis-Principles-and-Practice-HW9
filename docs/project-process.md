# 創作過程與 AI 分工

這份紀錄整理本次實際對話中的選擇，讓作業能呈現從規則、資料到網站的過程。它不是 Git commit 歷史，也不保證老師的評分或抄襲判定。

| 階段 | 使用者實際決定／檢視 | AI 協助工作 |
| --- | --- | --- |
| 主題 | 選擇 QWER，重視四位成員組團前經歷、作品與時間順序 | 規劃多頁架構與資料需求 |
| 規則 | 選擇簡單版 LLM Wiki、繁中搭原名、職涯重點 | 建立 AGENTS、來源紀錄、內容模板與查核規則 |
| 成員 | 要求寫出 Chodan 的 Twitch 身分；確認樣本後擴充其餘三人 | 查核並整理平台、代表經歷、加入過程，保留來源差異 |
| 作品 | 確認首張作品格式；決定合作影音與其他公開歌曲分開，LP 曲序未知保留待查 | 建立作品、逐曲簡介、版本對照與時間索引 |
| 活動 | 確認主要 12 筆加 A／B，共 14 筆活動 | 區分演出、典禮與音樂節目一位，保留日期辨識 |
| 推薦 | 指定 Dear、T.B.H、Dreamer；確認 12 首、四分類與網站導聆 | 整理推薦理由、版本、入口與來源，不冒充個人心得 |
| 視覺 | 選擇莓紅舞台風格、成員優先首頁、Astro、Showcase 合照 C 與個人照 B | 製作共用版型、響應式樣式、署名與素材紀錄 |
| 音樂操作 | 選擇 Spotify，黑膠先用圖形與公告，另加曲目索引 | 製作點擊載入播放器、搜尋、版本錨點 |
| 最終交付 | 要求一次完成其餘頁面、整理可上傳專案；當時決定自行上傳 | 完成樂團與推薦頁、根目錄 index.html、規則及發布指引，個資保留待填欄位 |
| 後續公開 | 於 2026-11-10 改為委託 AI 上傳至 Eugene-xyz 的既有 HW9 Repository 並啟用 Pages | 先確認既有內容、帳號與權限，再上傳及驗證公開結果；不把準備狀態當成已上線 |

較完整的實際更新紀錄見 [Wiki 日誌](../wiki/log.md)，原有決策與待查項見 [待查表](../wiki/questions.md)。本站文字與程式由 AI 協助整理與實作，題目、範圍、選曲、風格與多次調整由使用者參與決定。

## 如何展示自己理解這套規則

可以在說明或口頭展示時，挑一種內容示範：

1. 指出原始來源在 raw、整理後文章在 wiki、呈現版型在 src。
2. 說明新增作品為何需要版本 ID、發行日、曲表與來源；日期未知時如何處理。
3. 用事件模板說明「新聞日」與「演出日」的差別。
4. 修改一份 Wiki 後重新建置，展示列表、內頁及交叉連結如何沿用同一份資料。

## 提交前用自己的話補充

- 我為什麼選擇 QWER？
- 哪一項規則最能避免資料整理出錯？請舉本專案的實際例子。
- 如果之後新增一張專輯，我會讓 AI 依序讀哪些檔案、更新哪些資料？

這三題應由你依實際理解回答。保留資料來源、素材授權與 AI 分工；不把整段外站文章、其他同學成品或捏造的第一人稱心得當成自己的作品。
